# TAD workflow requirements

## Visual development record

Before every Git push:

1. Run the relevant Unity play test or validation for the change.
2. Capture at least one real in-game screenshot that visibly demonstrates the implemented or changed feature.
3. Add the capture and a concise description to the TAD living development catalogue.
4. Only then complete the normal validation and Git push workflow.

If Unity or the Game view is unavailable, do not silently skip the capture. Report the blocker to the user before pushing and wait for direction.

For non-visual infrastructure-only changes, capture the most relevant observable result (for example a settings screen, diagnostic result, or test outcome) and describe why it represents the change.
